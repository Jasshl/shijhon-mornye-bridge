Updates

{{ csrf_field(csrf) }}

The bridge checks its registries once a day and updates one extension at a time, between preparations. An update that keeps the extension's sign-in is installed right away. An update that would sign the extension out waits until the extension needs signing in anyway, and is installed before that sign-in.

With automatic updates on, this also installs updates that would sign an extension out; sign in again afterwards on the sign-in page.

Signed sessions

{{ csrf_field(csrf) }}

The host renews a signed session only when the extension makes a signed request in the last hour before the session expires. About fifty minutes before expiry the bridge makes one catalog search for a single result, never a song download. Extensions whose searches do not renew the session are shown as such on their cards.

Needs the keep-alive above. For an extension whose searches do not renew its session, the bridge starts preparing the last song that extension delivered, once in the last hour before the session expires, while that extension prepares nothing, and cancels it as soon as the session is renewed or the audio transfer begins. The audio is never kept or served. Some audio may be fetched before the cancel, and the service may count it as a short play on your account.

Preparation time and downloads

Each request waits up to {{ stream_wait }} seconds for a prepared audio file (default 8). A file that is still preparing answers 503 with Retry-After: 2 while preparation continues, so Shijhon can ask again within the add-on's time. Set budget_seconds to about {{ budget_seconds }} for each audio add-on in Shijhon, because preparing a file often takes longer than Shijhon's default.

Catalog support supplies metadata. Audio support prepares and serves files; downloads depend on the extension and Shijhon's download controls.
